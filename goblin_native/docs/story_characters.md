# ネームドキャラクター設計書

対象: `src/shared/data/story/stories.json`（改稿済み本文で登場） / `src/shared/data/enemy/*.json` / `src/shared/data/founderGoblin.ts`

改稿版ストーリーに登場するネームドキャラクターの一覧と、ゲームへの組み込み設計（味方=固有種ユニット、敵=ダンジョンのネームド敵）をまとめる。名前はすべて仮案であり、変更してよい。ただし変更時は `stories.json` 本文との同期を必ず取ること。

---

## 1. 味方ネームド（固有種ユニット）

マルク（`founderGoblin.ts` / raceId `founder`）と同じ「固有種」パターンで実装する。

### マルク【実装済み】

- 始祖ゴブリン。因子を取り込み群れへ波及させる異常個体。
- ストーリー全編の視点キャラクター。

### ギド — 固有種「古強者ゴブリン」

| 項目 | 内容 |
| --- | --- |
| 人物 | 群れ最古参の小柄なゴブリン。慎重派で口が悪い。マルクの異常さに最初に気づき、最初に信じた個体 |
| ストーリー登場 | prologue（初登場）→ story_after_forest（「一番前は俺だ」）→ story_after_goblin_village（「殺せ」と進言）→ **story_after_subjugation で戦死**（若い個体を庇い槍衾に倒れる） |
| ユニット加入タイミング | `story_after_forest`（同族との対峙）読了報酬。集落決戦の直前に前衛が加入する流れ |
| 性能方向 | 前衛タンク。低HP味方をかばう（`cover_low_hp_ally` 系）＋物理被ダメ軽減。ステータスは founder 比で HP/DEF 高め・ATK/命中低め |
| raceId 案 | `elder`（種族名「古強者ゴブリン」） |

**物語上の死とユニットの扱い**: order 13 で戦死するが、ユニットは削除しない（物語とプレイアブルの分離。一般的な手法）。推奨オプションとして、`story_after_subjugation` 読了時にギドへ固有スキル **「ギドの遺志」**（瀕死の味方を一度だけ庇って生存させる等）を付与する演出を入れると、死亡イベントがユニット強化として回収され、違和感が薄れる。

### ラグ — 固有種「疾風ゴブリン」

| 項目 | 内容 |
| --- | --- |
| 人物 | 無鉄砲な若い個体。最初に狼に乗り、骨を折っても笑って乗り直した初代ウルフライダー。終盤、最初にマルクを「王」と呼ぶ |
| ストーリー登場 | story_after_wolf_grassland（初騎乗）→ story_ending（戴冠の口火） |
| ユニット加入タイミング | `story_after_wolf_grassland`（狼を駆る者）読了報酬。ライダージョブ解放（`goblinJobs.ts` の `unlockRequiresReadStory: "story_after_wolf_grassland"`）と同時に加入し、ジョブの顔になる |
| 性能方向 | 高速アタッカー。回避・攻撃回数寄り。ライダー適性が高い設計 |
| raceId 案 | `gale`（種族名「疾風ゴブリン」） |

### ドマ — ユニット化しない（伝承キャラ）

- プロローグ以前に「先に歩かされて戻らなかった」故人。マルクの原点となる喪失であり、生存キャラにしない。
- 拡張オプション: ネクロマンサーサイドの追加エピソードで「ドマの骨との再会（蘇らせるか、眠らせるか）」を描くと、死霊術テーマとマルクの原点が交差する強いイベントになる（第二部候補）。

### 実装メモ（味方固有種）

1. `founderGoblin.ts` を一般化した `namedGoblinSeeds.ts` を追加（id / name / raceId / 初期ステータス / defaultSkillIds）。
2. `StoryReward` に `named_goblin` 種別を追加し、`useStoryStore` の報酬処理で seed から生成して `addPendingGoblin` する（`goblin`（亜種因子）報酬とは別系統）。
3. `races.ts` / `Race.ts` に `elder` / `gale` を追加。
4. アバター画像が必要: `assets/goblin/gido.png`, `assets/goblin/ragu.png`（未作成）。
5. ステータス実数値はバランスシミュレーション（`docs/balance_simulation.md`）で検証してから確定する。

### 実装メモ（敵ネームド）

1. 各エリアの敵DB（`src/shared/data/enemy/<area>.json`）のボスエントリを、上記の名前に `name` 変更（例: `"名前": "沼王ザール"`）。id は既存のまま変えない（ドロップ・パターン参照を壊さないため）。
2. ロランのように複数エリアへ跨がるキャラは、エリアごとに別エントリ（別id・別ステータス）として定義し、名前だけ揃える。
3. ステータスは `docs/balance_reference.md` の算出基準（算出式×標準倍率、命中/多段は例外扱い）に従い、変更後は計測ツールで検証する。
4. ロラン・グレアム・アレン・オルダス王は専用アセットが必要（既存の frontier_knight / frontier_knight_captain / human_warrior の流用で仮対応可）。

## 3. 名前と本文の同期ルール

- ストーリー本文（`stories.json`）で名前を出しているのは、味方: **ドマ / ギド / ラグ**、敵: **グレアム / ロラン / アレン / ガリウス（元帥）/ ザール（沼王）/ バルガム（鍛冶王）**。種族ボスは基本は肩書で呼び、敵データ側の名前と一致させる場合のみ本文にも名前を出す（沼王ザール・鍛冶王バルガムはイベントストーリーで名前入りに昇格済み）。
- 敵データに名前を付けたあと、余裕があれば本文の肩書を「沼王ザール」のように置き換えてよい（必須ではない）。
- 名前を変更する場合は、このドキュメント → 敵データ → stories.json の順に揃える。

## 4. 実装ステップ（推奨順）

1. **敵ネームド化**（アセット不要・低リスク）: 各敵DBのボス `name` をリネーム。ロランの中ボス追加は `subjugation_force_1` / `royal_capital_2` の編成調整とセットで。
2. **ギド・ラグの固有種ユニット**: アバター作成 → `namedGoblinSeeds.ts` → `named_goblin` 報酬型 → races 追加 → バランス検証。
3. **「ギドの遺志」演出**（オプション）: story 読了トリガーでのスキル付与。
