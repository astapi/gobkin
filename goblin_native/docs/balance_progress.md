### 2.5 レア再設計の効果と最適構成 — 「レアは強すぎたのか」検証(2026-07-11)

当初「レア再設計の効果は劇的(高Tierが >300 → 120 に激減)」と見立てたが、切り分けの結果**大半は計測アーティファクトで、レアの素ステータスは過剰ではない**と判明した。

**対照実験(オーク野営地T3、編成・隊列を固定し装備だけ差し替え、20シード成功率)**:

| Lv | A: スキル込みレア | B: 素ステ順レア | C: 通常装備のみ(新スキルほぼ無し) |
|---|---|---|---|
| 120 | **80%** | 0% | 15% |
| 130 | **80%** | 0% | 25% |
| 140 | 100% | 100% | 100% |

読み取り:
1. **レアの素ステは過剰ではない**。通常装備のみ(C)でも Lv140 で100%クリアし、レア(B)と横並び。むしろ素ステ順にレアを積むと武器の `attackCount -0.2` が重なって一時的に弱くなる。「ステータスが壊れている」状態ではない。
2. **効いているのは新スキル**。スキル価値で装備選定(A)すると Lv120 で攻略でき、通常のみ(C)の Lv140 相当を **約20レベル前倒し**。鬨の声(PT+30%)・氷霧の大渦(全体魔法)・癒しの霊気・物理障壁などパーティ効果が本体で、これは「スキル解禁で高Tierを攻略可能にする」設計意図どおり。
3. **>300 という旧数字は計測バグ由来**(§第3期)。同一敵データを正しく測ると真の閾値は Lv120〜150 で、レアが壁を破壊したわけではない。

**最適構成の型**(probe が到達した構成。エリアによらずほぼ共通):
- 隊列: 前衛3(guard + warrior + thief/hobgoblin亜種) / 後衛3(cleric×2 + mage)。リザードマン沼では rider 採用。**この編成自体は標準探索でも同じで、PT構成は既に最適化されている**。
- コア装備: 戦商隊のファルシオン(吸血12%+人間特効2.0) / 墓守の剣(闘志+不死特効2.0) / 王都護衛の盾(物理障壁3回)。tail に聖杯ロッド・滅び村のワンド(氷霧の大渦)・商隊ロッド(癒しの霊気20)・彷徨いの指輪(鬨の声1.3)等が入り、Lv120で装備枠18・付与スキル延べ38種が同時稼働する。
- 高レベル帯は装備枠が18〜23あるため、スロット単位の最適化より「新スキルレア(特にPT効果)を何枚束ねられるか」が支配的。

**潜在的な過大評価(未解決の留意点)**: シミュレータはボス1体ドロップのユニークレアを**6体全員に複製**して装備させる(在庫・入手コストを無視)。今回は複製あり/各1個/通常のみが横並びで実害は出なかったが、単一の突出レア1個で支配的になるビルドでは天井を過大評価しうる。

**計測手法の結論**: `measureTiers.js` の strategist 高Tier値は Lv3盲目探索のため信頼できない(§第3期)。信頼できる高Tier閾値は `probeOptimalBuild.js`(§5、高レベルで探索＋スキル価値で候補選定)を使う。

## 3. 設計方針(重要・誤修正しないこと)

- 高Tier(伝説/恐ろしい)は**実装済みの範囲で攻略可能**だが、これは「レアが強すぎる」からではなく、①計測バグ是正で真の閾値(Lv120〜150)が見えた ②新スキルが約+20Lv寄与、による(§2.5)。**レアの素ステを弱体化する対応は不要**(通常装備と同等ステで、過剰ではない)。

## 7. ゲーム開始から討伐戦防衛戦までのプレイ時間(2026-07-11)

`scripts/simulate-playtime-to-dungeon.js` を追加し、ゲーム開始から `subjugation_force_1` の初回クリアまでを、経験値周回と装備周回を含めて試算した。対象ルートは以下のメイン進行。

```text
スライムの洞窟 → 周辺の森 → ゴブリン集落 → 森外れの廃村 → 古井戸の地下水路
→ 忘れられた廃墟 → 盗賊のアジト → 街道 → オークの野営地 → 辺境の村
→ ウルフ草原 → リザードマンの沼砦 → オークの砦 → vs討伐隊防衛戦
```

### 7.1 結果

| 周回方針 | 経過時間 | 初回クリア | レベル上げ | 装備集め | レベル上げの主な内容 |
|---|---:|---:|---:|---:|---|
| 最新ダンジョンを周回 | **146.8時間 / 6.1日** | 33.5時間 | 113.2時間 | 9.0時間 | 古井戸を110周してLv30→40 |
| 経験値/時間が最大の場所を周回 | **61.9時間 / 2.6日** | 33.5時間 | 19.7時間 | 9.0時間 | スライムの洞窟を計約7,100周 |

両方とも、現行 `strategyPremium.csv` の Tier0・strategist 80%到達レベルを採用した。ゴブリン集落クリア後は2PTとして、rank3/rank4装備の周回を並列化している。2PTは主PTの経験値獲得速度を2倍にはしていないため、レベル上げの大部分は短縮されない。

### 7.2 読み取り

- 現在のタイマー設定だけを見ると、初回クリアだけで **33.5時間**。総時間の主因は初回クリアよりレベル上げになる。
- 「経験値/時間が最大の場所」を選ぶと、**スライムの洞窟が約36.8EXP / 10秒**で最も効率が高く、序盤ダンジョンへの戻り周回が極端に有利になる。
- これはプレイヤーが合理的に選べる仕様である一方、体験としては「Lv30〜40までスライムの洞窟を数千周する」ため、意図した周回先でないなら経験値・再周回時間・経験値補正の見直し候補になる。
- 装備周回は近似値として rank2=2周、rank3=3周、rank4=4周を置いた。レア装備の特定品を揃える場合は、実ドロップ率に応じてこの部分が増える。
- 表の「初回クリア・レベル上げ・装備集め」は重複を含む内訳であり、並列化分を差し引いた経過時間とは単純加算にならない。

```bash
npm run sim:playtime -- --through subjugation_force_1 --farm-policy latest \
  --out reports/playtime-subjugation-latest.json
npm run sim:playtime -- --through subjugation_force_1 --farm-policy best-xp-hour \
  --out reports/playtime-subjugation-best.json
```

詳細出力: `reports/playtime-subjugation-latest.md` / `reports/playtime-subjugation-best.md`。経過時間はタイマー時間であり、周回開始・報酬回収などの手操作時間、敗北による再挑戦、プレイヤーごとの編成差は含めない。

### 7.4 プレイ時間シミュレーションの考え方

このシミュレーションでは、時間を2種類に分けて考える。

1. **遠征経過時間**: 遠征を開始してから帰還するまでのタイマー時間。アプリを閉じていても進む。今回の146.8時間は主にこの値で、連続稼働できるなら約6.1日になる。
2. **実操作時間**: 周回を開始する、報酬を受け取る、編成・装備を変更するなど、プレイヤーが実際に画面を触る時間。現行シミュレーターではまだ別計測していない。

したがって、`146.8時間 ÷ 3時間/日 = 約49日` という換算は、「146.8時間すべてが実操作時間だった場合」の上限寄りの見積もりである。遠征が放置中も進む現在の仕様では、カレンダー上は約6.1日だが、1日3時間のプレイ時間で何周を開始・回収できるかは別途モデル化する必要がある。

計算の基本式は以下。

```text
経過時間
  = 初回クリア時間の合計
  + レベル上げ周回時間
  + 装備周回時間
  - 2PTで重複できた時間
```

- **初回クリア**: `exploration_time_sec_first` を使用。メインルートの解放は順番に進むため、初回クリア時間は基本的に直列で加算する。
- **通常周回**: `exploration_time_sec` を使用。経験値は各フロアのランダム戦闘、フロア終了戦闘、最終ボスの期待値から求め、初回クリアと通常周回で異なる所要時間・経験値を使う。
- **レベル上げ**: `latest` は直前にクリアしたダンジョン、`best-xp-hour` はクリア済みダンジョンの経験値/時間が最大の場所を選ぶ。後者は経験値だけを目的にした理論下限であり、ドロップ価値を十分に評価しない。
- **装備集め**: rank2=2周、rank3=3周、rank4=4周という近似周回数を置く。特定レア装備を狙う場合は、実際のドロップ率から増やす。
- **2PT**: ゴブリン集落クリア後に2PTになる前提。別PTで装備周回などを並列化するが、主PTの経験値獲得量を2倍にはしない。初回クリアのメインルートも直列のまま。

このため、バランス評価では次の3つを分けて記録するのが望ましい。

- **タイマー経過時間**: プレイヤーが触らなくても進む、ゲーム内の待ち時間。
- **実操作時間**: 周回開始・回収・編成変更に必要な時間。
- **プレイ日数**: タイマー経過時間と実操作時間を、1日のプレイ可能時間・ログイン頻度・同時出撃数から換算した値。
