# ゴブリン誕生システム

## 概要

ゴブリンはダンジョンを完全制圧した際に1体誕生する。
誕生時に個体値・ステータス・因子引き継ぎ・亜種化がすべて決定される。

## 誕生のトリガー

### 条件

以下の**両方**を満たした場合にゴブリンが1体誕生する:

1. `replay.summary.success === true`（遠征成功）
2. `replay.summary.maxFloorReached >= dungeon.floors`（ダンジョン全フロア到達＝完全制圧）

### 誕生数

**1回の制圧につき1体**。複数体同時に誕生する仕組みはない。

### 処理の流れ

```
ダンジョン制圧
  │
  ├─ ① ダンジョンをクリア済みにマーク
  ├─ ② nextGoblinId を採番（アトミックインクリメント）
  ├─ ③ GoblinBirthService.createNewGoblin() でゴブリン生成
  │     引数: nextId, undefined(IV), goblins(拠点全員), areaLevel, rank
  │
  └─ ④ 保存先の振り分け
        ├─ 拠点に空きあり → goblins テーブルに直接保存
        └─ 容量超過 → pending_goblins テーブルに待機保存
              └─ 待機数が上限（ランク×5）に達している場合は誕生しない
```

## 誕生の処理詳細

### GoblinBirthService.createNewGoblin()

```
引数: (nextGoblinId, individualValue?, baseGoblins?, areaLevel?, baseRank?)
  │
  ├─ 1. 個体値の決定
  │     ├─ individualValue 指定あり → そのまま使用
  │     ├─ areaLevel + baseRank 指定 → calculateIndividualValue() で自動計算
  │     └─ いずれもなし → デフォルト値 1
  │
  ├─ 2. 因子引き継ぎ評価（baseGoblins がある場合のみ）
  │     ├─ 親選出（拠点から最大2体）
  │     ├─ 各因子の引き継ぎ判定
  │     └─ 亜種化判定
  │
  └─ 3. ゴブリン生成
        ├─ 名前のランダム選択
        ├─ 種族・アバターの決定（亜種 or 通常）
        ├─ 基本能力値に基づく基礎ステータス生成
        ├─ 実効ステータス計算（因子適用）
        └─ Goblin オブジェクト返却
```

## 個体値システム

### 概要

個体値（IV: Individual Value）は1〜64の整数値で、ゴブリンの潜在能力を表す。

### 計算式

```
個体値 = clamp(1, 64, baseIV + bonus)

baseIV = floor(min + (max - min) × random())   ← エリアレベルで範囲決定
bonus  = BASE_RANK_BONUS[拠点ランク]
```

### エリアレベルごとのベース範囲

| エリアレベル | 範囲 | 対応ダンジョン例 |
|-------------|------|----------------|
| 1 | 1〜8 | スライムの洞窟、周辺の森 |
| 2 | 6〜14 | ゴブリン集落、忘れられた廃墟 |
| 3 | 12〜20 | オークの野営地、vs討伐隊防衛戦 |
| 4 | 18〜28 | 辺境の村 |
| 5 | 26〜36 | ドワーフ坑道、エルフの隠れ里 |
| 6 | 34〜44 | リザードマンの沼砦、トロルの峡谷 |
| 7 | 42〜52 | 人間の城塞 |
| 8 | 50〜60 | 王都決戦 |

### 拠点ランクボーナス

| ランク | ボーナス | 解放条件ダンジョン | ランクアップ費用 |
|--------|---------|------------------|--------------|
| 1 | +0 | 初期 | - |
| 2 | +2 | ゴブリン集落・中枢 | 100G |
| 3 | +4 | オークの野営地・本陣 | 500G |
| 4 | +6 | vs討伐隊防衛戦 | 1,500G |
| 5 | +8 | ドワーフ坑道 | 4,000G |
| 6 | +10 | 人間の城塞 | 10,000G |
| 7 | +12 | 王都決戦 | 25,000G |

### 個体値の理論値

- **最低**: エリアLv1 + ランク1 = 1〜8（ボーナスなし）
- **最高**: エリアLv8 + ランク7 = 50+12〜60+12 = 62〜64（上限64でクランプ）

## 基礎ステータス生成

### ステータス範囲

種族ごとの基本能力値を基準に、誕生時に各能力値へ `-5〜+3` のランダム補正が入る。
レベルアップ時は各能力値が1レベルごとに+1され、種族ごとの最大値（種族基準値+10）で止まる。

例: 純ゴブリンの基準値は全能力10、最大値は全能力20。Lv1で10ならLv11、Lv1で5ならLv16で最大値に到達する。

戦闘ステータスは基本能力値と式で決定される:

| ステータス | 最小 | 最大 | 備考 |
|-----------|------|------|------|
| HP | 55 | 80 | |
| ATK | 10 | 16 | |
| DEF | 種族・Lv依存 | 種族・Lv依存 | |
| 命中精度 | 60 | 70 | |
| 回避 | 9 | 14 | |
| 攻撃回数 | - | - | 種族（血統）で固定値が決まる |

### 攻撃回数（血統別）

| 種族 | 攻撃回数 |
|------|---------|
| ゴブリン | 2 |
| スライムゴブリン | 2 |
| ウルフゴブリン | **3** |
| オークゴブリン | 2 |
| ホブゴブリン | 2 |
| その他（未定義） | 2（デフォルト） |

## 名前の決定

### 名前プール

160個の和風ゴブリン名からランダムに1つ選択される。重複制限はない（同名のゴブリンが複数存在しうる）。

名前の例: グリム、ゴブタ、ボブ、ゴロー、クロ、シロ、ゴブ右衛門、ゴブ左衛門、ガッツ、ゾロ、ゴンベ、チャド など

## 拠点容量と待機システム

### 拠点ランクごとの容量

| ランク | 最大ゴブリン数 | 最大パーティ数 | 待機上限 |
|--------|-------------|-------------|---------|
| 1 | 10 | 1 | 5 |
| 2 | 20 | 2 | 10 |
| 3 | 35 | 3 | 15 |
| 4 | 50 | 4 | 20 |
| 5 | 70 | 5 | 25 |
| 6 | 100 | 6 | 30 |
| 7 | 150 | 8 | 35 |

※ 待機上限 = ランク × 5

### 容量超過時の挙動

1. **拠点に空きあり**: `goblins` テーブルに直接保存、即座に使用可能
2. **拠点が満員**: `pending_goblins` テーブルに待機保存
3. **待機枠も満杯**: ゴブリンは誕生しない（消失）

## ID管理

### nextGoblinId

- `base_state` テーブルの `next_goblin_id` カラムで管理
- `getAndIncrementNextGoblinId()` でアトミックにインクリメント
- 初期値: 1

```sql
UPDATE base_state SET next_goblin_id = next_goblin_id + 1 WHERE id = 1
```

## 実効ステータス計算

誕生時に `GoblinStatCalculator.calculate()` で因子を加味した実効ステータスが計算される:

```
実効値 = floor( (基礎ステ + 因子ボーナス + 装備フラット + スキルフラット) × (1 + 装備% / 100) )
```

誕生時は装備なしのため:

```
実効値 = 基礎ステ + 因子ボーナス + スキルフラット
```

## 初期状態

誕生したゴブリンの初期値:

| フィールド | 初期値 |
|-----------|--------|
| level | 1 |
| experience | 0 |
| factors | 引き継ぎ結果（なければ空配列） |
| variantFactorId | 亜種の場合のみ設定 |
| spells | なし |
